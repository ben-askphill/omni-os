# Known limits

- Isolation is a worktree plus a browser profile, not a VM. Threads run with `bypassPermissions` because nobody can answer prompts headless; the write boundaries in your workspace folder's CLAUDE.md still apply.
- Only one live thread per channel gets the persistent browser profile; parallel ones get an isolated browser. The channel's Chrome closes after 5 idle minutes.
- Worktrees clean themselves up (`apps/server/worktree-sweep.ts`). A thread's worktree is removed with `git worktree remove` in its own repo when the thread is archived or deleted, or when its branch is merged (into origin's default branch, or its PR is merged) and it has been idle for 7 days (`OMNI_WORKTREE_IDLE_DAYS`). It never removes a worktree with uncommitted or untracked changes, with commits no remote has, or of a running thread; those are kept and logged. The pass runs a minute after startup and then daily, plus right away on archive, and runs `git worktree prune` in each repo it touched. Branches are kept, so reopening the thread checks its branch out again. `OMNI_WORKTREE_SWEEP=0` turns it off.
- Restarting the server ends running turns as failed. Messages that had not reached a harness yet are kept as `recovered` and wait for Resume; one that may have reached it is marked `uncertain` and goes again only when you say so.
- Subscription limits still apply. Each harness has its own concurrency cap (4 by default): `OMNI_MAX_CONCURRENT` (Claude Code), `OMNI_MAX_CONCURRENT_CODEX`, `OMNI_MAX_CONCURRENT_CURSOR`, `OMNI_MAX_CONCURRENT_HERMES`. A full harness never holds up threads on another. Hermes also enforces its own concurrent-run cap; Omni backs off and retries on HTTP 429.
