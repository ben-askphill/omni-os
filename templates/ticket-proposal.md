Turn this ticket into a proposal and a reply: $ARGUMENTS

1. Read the ticket and everything it links to: comments, designs, related tickets, the code or pages it touches.
2. Write a proposal: the problem in one line, what you would change, what stays out of scope, risks, and open questions for the requester. Describe scope and steps, never a time estimate.
3. Draft a short comment for the ticket that sums up the proposal and asks the open questions.
4. Show the proposal and the comment. Post the comment only after I say so.
